## 🏆 Data Mining Competition Experience (Semester 3)

Three national-level data mining competitions, all using deep learning. Code and datasets cannot be published under the organizers' rules, so below I describe the approach and the technical findings.

| Competition | Task | Approach | Result |
|---|---|---|---|
| **INFEST** | Image classification | DINO (fine-tuning), class imbalance handling | Preliminary round, rank **31 of 89 teams** · [Certificate](https://drive.google.com/file/d/16lxTXY2BjMiBvxsSUAWoTnHSHQS7RM8X/view?usp=sharing) |
| **DATASCAPE** | Image classification | DINO, done **individually** (team competition) | Preliminary round |
| **Action UNESA** | Text classification | IndoBERT, IndoBERTweet, XLM-R | Preliminary round |

**My role:** I handled most of the technical pipeline: EDA, preprocessing, feature engineering, modelling, and evaluation. In the two team competitions, my teammates wrote the reports.

### What I learned
- **DINO > ResNet50** for image classification: the pretrained representations are already richer.
- **Fine-tuning > training from scratch.** With limited data, the gap is clear.
- **Fully frozen backbones underperform.** Some layers need to be unfrozen.
- **Class imbalance must be handled explicitly.** Otherwise minority-class performance drops.
- **IndoBERT does better on formal Indonesian, IndoBERTweet does better on slang and social media text.** Model choice should follow the language style of the data.
- **I tested XLM-R only partially and did not use it.** My final focus was IndoBERT and IndoBERTweet.

> Biggest lesson: well-documented experiments are worth more than one good score.
